## 一、技术栈识别（第一步 1.1）

| 维度 | 识别结果 |
|---|---|
| 前端框架 | **无框架**——单文件原生 HTML/CSS/JS 控制台（`public/index.html`，9088 行 / ~397KB），PWA（`manifest.webmanifest` + `sw.js`） |
| 后端框架 | **无框架**——Node.js ≥18 原生 HTTP 服务（`server.js` ~195KB / ~4800 行）+ `src/` 模块化（routes / store / security / scheduler / cdp / logger / codex） |
| 构建工具 | Web 端无构建（零依赖直跑）；Android 用 Gradle（Kotlin DSL）；Windows 用 dotnet/VS（WPF）；macOS 用 Xcode/SwiftUI |
| 包管理器 | npm（`package.json`，**零 dependencies / devDependencies**，无 lock 文件） |
| 语言 | JavaScript（Node 服务端 + 前端）、Kotlin（Android Compose）、C#（WPF）、Swift（SwiftUI） |
| 数据库/ORM | SQLite（better-sqlite3 可选）优先，JSON 文件回退；Codex 会话为 `.codex/sessions/*.jsonl`；无 ORM |
| CSS 方案 | 原生 CSS + 64 个自定义变量（双主题 black-sky / white-night） |
| 其他关键设施 | CDP WebSocket 通道、自研 cron 调度、token bucket 限流、X.509 证书链（纯 Node 生成）、LRU 静态缓存 |

> 结论：这是一个「零 npm 依赖」的纯 Node 服务 + 三端壳工程（Android/WPF/SwiftUI）的本地桥接工具，无传统前端构建链，垃圾清理重点在**构建产物、嵌入式副本与未引用静态资源**，而非依赖缓存。
