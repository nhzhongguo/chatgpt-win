# 06 · 综合升级路线图

> 项目：Codex Remote Bridge（Chat 远程连接）v4.0.0

> 日期：2026-08-04 ｜ 口径：以"零 npm 依赖"定位为底线，所有引入项保持零依赖或纯前端方案

## 一、升级全景（从五份报告提炼）

| 维度 | 现状结论 | 主要差距 | 来源 |
|---|---|---|---|
| 工程卫生 | 良好；无依赖缓存/日志/空目录/废弃配置 | 34MB 构建产物可回收；macOS 内嵌副本陈旧且被 git 追踪；3 张安装图 + 4 个小图标未引用 | 01 |
| UI | Web token 化优秀（64 变量/双主题/a11y 达标）；Android token 化完成；WPF/macOS 半 token 化 | Web 骨架屏缺失、`#f1f1f1` 未收敛；WPF ~38 处内联 hex；macOS 色板散落无命名；Android 无浅色主题/失败态 UI | 02 |
| 性能 | 架构健康；已修复 5 处低风险热点（静态缓存 stat、队列 O(1)、附件索引、WS 背压等） | `/codex/status` 轮询全量重读（最大热点）、历史大文件双重解析、线程列表全量 walk、前端 localStorage 每轮全量写 | 03 |
| 功能对标 | 33 个真实开源项目对标（详见 04 xlsx）；核心架构（CDP/App-Server 双通道、SQLite 队列、cron、证书链）居社区前列 | P0：语音输入/输出、对话导出、提示词库；P1：定时任务时区、全文搜索、文件传输；P2：截图预览、token 分级等 | 05 |

**总原则**：不做架构重构、不引入重依赖；按「P0 体验补全 → 低风险 UI/性能收敛 → P1 能力延伸 → P2 可选」推进，每阶段以 `npm run check` + `node --test test/` + 端到端冒烟为门禁。

## 二、分阶段执行计划

### Phase 0 · 工程清理（0.5 天）

| # | 任务 | 产出 | 门禁 |
|---|---|---|---|
| 0.1 | 按 `01-清理报告.md` §4.1 执行 C1~C5（回收站删除） | 磁盘释放 ~35.4MB，回填 §4.3 前后对比 | 删除后 `git status` 干净；服务可正常启动 |
| 0.2 | C6：`git rm -r --cached macos/.../CodexMiniProject` + .gitignore 追加该目录 | 仓库瘦身 ~1.7MB | `git status` 确认；macOS 下次构建由脚本自动刷新 |
| 0.3 | 发布流程补丁：README/BUILDING.md 注明"内嵌副本由构建脚本生成，勿手动提交" | 文档更新 | 文档评审 |

> 风险：极低。C6 需确认 Xcode 工程引用为文件夹引用（脚本 rsync 后 xcodebuild，构建不受影响）。

### Phase 1 · P0 手机端体验补全（3~4 天）← 对标社区标配（LobeChat/Chatbox/lencx）

| # | 功能 | 方案（零依赖） | 工作量 | 验证 |
|---|---|---|---|---|
| 1.1 | 语音输入 STT | Web Speech API `SpeechRecognition`（zh-CN，interimResults） | 0.5~1 天 | 手机浏览器/Android App 说话→输入框出中文；权限拒绝有提示 |
| 1.2 | 语音输出 TTS | `speechSynthesis` + 助手气泡喇叭按钮 + 停止/防串音 | 0.5~1 天 | 中英朗读；连续点击不重叠；切线程 cancel |
| 1.3 | 对话导出 Markdown | 新增只读 `GET /codex/export`（复用 parseCodexThreadHistory）+ Blob 下载 | 0.5~1 天 | `node --test test/server.test.js` 通过；导出文件内容完整 |
| 1.4 | 提示词库 | state.json 增 `promptLibrary` 字段 + `/codex/prompts` CRUD + 输入框快捷插入 | 0.5~1 天 | 增删后刷新仍在；旧 state.json 兼容（空数组） |

> 门禁：`npm run check` + 全量测试 38/38 + 手机端真机冒烟（导出/语音各 1 条用例）。

### Phase 2 · UI 低风险收敛（2.5~3 天）

| # | 任务 | 端 | 内容 | 工作量 | 风险 |
|---|---|---|---|---|---|
| 2.1 | 消息骨架屏 | Web | 首次/新会话加载 CSS 骨架（shimmer，reduced-motion 降级静态） | 1 天 | 中 |
| 2.2 | `#f1f1f1` 收敛 | Web | 新增 `--hover-bg-soft` 等 token，替换浅色区 7 处，双主题校验 | 0.5 天 | 中 |
| 2.3 | WPF 组件级 Brush | Windows | ~38 处内联 hex 抽为命名资源 | 1 天 | 中 |
| 2.4 | macOS 色板命名 | macOS | `private extension Color` 集中色板，替换散落值 | 0.5 天 | 低 |
| 2.5 | Android 失败态 UI | Android | WebView 失败内嵌重试/回退视图（替代仅 Snackbar） | 0.5 天 | 中 |

> 门禁：Web 端双主题视觉比对截图；WPF 本地编译；Android `./gradlew assembleDebug`（CI 有 lint+test+assemble 兜底）。
> 不做：Android 浅色主题/动态取色、P3 灰阶全量合并（收益/风险比低，滚动排期）。

### Phase 3 · 性能优化（3~4 天）

| # | 优化项（对应 03 §二） | 内容 | 工作量 | 预期收益 | 风险 |
|---|---|---|---|---|---|
| 3.1 | 项 6：`parseCodexStatus` 增量解析 | 按 since 增量解析 + 进程内 size/mtime 缓存（追加行增量） | 1.5~2 天 | 轮询 CPU 降 60~90% | 中高（需回归 38 测试 + 长会话压测） |
| 3.2 | 项 11：serializeMessages 最终态写入 | 仅 complete/error 写 localStorage | 0.5 天 | 手机端磁盘/内存压力下降 | 低 |
| 3.3 | 项 8：线程列表活跃优先 + TTL 提升 | 按 mtimeMs 排序先处理 + TTL 1.2s→3s（配合前端 4.5s 轮询） | 1 天 | 会话 >200 时列表延迟减半 | 中 |
| 3.4 | 项 12：请求级 P50/P95 观测 | Logger 按路径聚合，`/codex/stats` 扩展 | 0.5 天 | 量化优化效果 | 低 |

> 门禁：全量测试通过；4.2-C 轮询 CPU 对照（优化前后 node CPU%）；长会话（>48MB）历史延迟对照（项 7 顺带评估）。
> 不做：项 9/10（微秒级收益）、项 7 单遍解析（视 3.1 后实测再定）。

### Phase 4 · P1 能力延伸（3~5 天）

| # | 功能 | 方案 | 工作量 | 验证 |
|---|---|---|---|---|
| 4.1 | 定时任务时区 | CronParser 增 `timezone`（Intl 换算）+ 任务记录字段 + 表单下拉 | 1 天 | 纽约/上海对照；非法时区 400；旧任务兼容 |
| 4.2 | 历史全文搜索 | `GET /codex/search`：jsonl 尾部受限 grep + 片段高亮，限 50 条 | 1~2 天 | 中英文命中；<2 字符 400；单次 <2s |
| 4.3 | 通用文件下载 | `GET /codex/download`：白名单目录 + 前缀校验防穿越 + 20MB 上限 | 1 天 | 正常下载 / `../` 403 / 超大 413 |
| 4.4 | 上传方向（可选） | 文档类附件 → 写入 Codex cwd 供 `/add` 引用（评估后定） | 1 天 | 端到端 /add 流程 |

> 门禁：每项新增对应 test 用例（时区换算、穿越防护、搜索限流），全量回归。

## 四、风险评估

| 风险 | 等级 | 影响面 | 缓解措施 |
|---|---|---|---|
| `parseCodexStatus` 增量解析引入状态错乱（漏消息/重复统计） | 高 | 手机端状态显示、审批流 | 保留旧实现作开关；构造多会话长日志回归；灰度对比 4.2-C |
| Web 单文件 9088 行 index.html 大改引发样式回归 | 中 | 双主题全部页面 | 每个 token/骨架改动做 black-sky/white-night 截图对比；改前 git 打点 |
| 内嵌 macOS 副本取消追踪后克隆构建失败 | 中 | macOS 发布 | 构建脚本 rsync 已内建（`--delete` 刷新）；BUILDING.md 注明"构建前必跑脚本" |
| WPF 38 处 Brush 收敛漏改导致 UI 走样 | 中 | Windows 壳 | 逐资源 diff；本地编译 + 截图回归 |
| 功能对标项超卖（04 xlsx 中 100+ 目标 vs 实际 33 项） | 低 | 功能决策 | 已按 P0/P1/P2 与成本排序，05 明确"按使用频次×实现成本"取舍 |
| 导出/搜索对超大会话（>128MB）超时 | 中 | 手机端可用性 | 导出沿用 120 条上限；搜索限 2MB 尾部 + 50 条结果 + 2s 预算 |
| Android 变更无本地 Gradle 验证（依赖下载耗时） | 中 | Android 发布 | 依赖 CI（lint + testDebugUnitTest + assembleDebug）；本地改动保持纯替换风格 |
